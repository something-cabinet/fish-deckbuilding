Session 2026-08-04: restructured the engine into a domain-layered layout (spec wiki:specs/domain-layered-engine-structure, approved). Every domain (cards/units/battle/deck) now owns model/ + rules/ + application/ + data/; shared/helpers holds pure plumbing; services/, helpers/, and root data.ts are DELETED. The 547-line engine.service god module was decomposed into domain-owned files: cards/rules/targeting, cards/application/effects (resolver), units/rules/combat, battle/rules/{board,state,turn}, battle/application/{actions,commands,session}, deck/rules. Player actions (move/attack/cast/sell/buy) are application orchestration in battle/application/actions.service (D3). icons moved to src/components/game/card-icons.ts (was importing lucide-react into the pure engine — presentation leak). KEY LEARNINGS: (a) the effects↔engine runtime cycle is gone — root cause was cross-domain VALUE imports of the battle BARREL (FxKind/Phase/COLS); fix = import the runtime-leaf segment `battle/model` from cards/units/deck/shared, never the full battle barrel (D5); symptom of a barrel cycle is `Module "...battle" has no exported member 'X'` on exports that DO exist; (b) duplicated dealDamage/drawCards/shuffle were consolidated into units/rules/combat + deck/rules; (c) `export *` barrels throw TS2308 "already exported" if the same name is re-exported twice (selectUnit was defined in both state.service and actions.service — keep one home); (d) `resetIds` added to shared helpers for deterministic SSR id seeds; (e) moved files need their relative import depths fixed (../battle → ../../battle) and the JSON pack path shifts (cards/pack → cards/data/../pack-01-starter.json). Verified: tsc 0, 66/66 tests, next build green, zero stale services/helpers refs.
